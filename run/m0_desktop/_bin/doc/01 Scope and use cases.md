# Scope

## What we have here...

> -zero started small as data modelling and diagramming environment, but year after year it exploded in many resonable areas - all those functionalities when combined in one platform creates a starting point for many extra-interesting use cases. 

The core -zero properites and functionalities are:
- **_Meta-Vertex Edge Graph (MVEG)_** 
	- a core data structure
	- extreme simplicity and unlimited meta / semantic expressivity
	- same and coherent behaviour, properties and tooling on all the levels of data instance / any meta 
- **Graph DB** 
	- persistent storage of any data / meta data
	- complex querying
	- automatic indexing
	- triggers
	- transactions
	- updatable views
	- _MVEG_ based
- **Modeling**
	- representing complex data and knowledge in form of _MVEG_
		- static system's properties
		- dynamic system's properties
		- anything that can be described by spoken language or mathematics
	- _meta_ modeling with any number of _meta_	
	- relations between models / meta-models
	- model transformation
	- build in meta models
	- easily defined custom meta models
		- meta models are graph fragments
- **Diagrams**
	- graph = diagram
	- visual representation of any data and models
	- rich library of diagram primitives
		- diagram primitives are graph fragments
	- easily defined user diagram types and diagram primitives
		- diagram types are graph fragments
	- nested diagrams and multiple diagrams for the same data 
		- diagrams are graph fragments
- **Text languages**
	- graph = text
	- build-in graph ⇔ text languages
	- easily defined custom graph ⇔ text languages
	- graph ⇔ text languages algebra
		- can inherit languages
		- can mix multiple langages
	- graph ⇔ text languages definition are graph fragments
- **Graph Virtual Machine**
	- graph = code that _GVM_ can run
	- turing complete
	- currently based on object oriented paradigm 
	- can support any execution paradigm with custom execution engines
	- updatable views on code
	- developer has access to advanced platform features such as:
		- transactions
		- triggers
		- views
		- persistent storage
	- rich library supporting:
		- REST end-points server
		- consuming existing REST services
		- HTTP server
		- JSON
		- Markdown
- **Platform**
	- diagram = graph = text
		- core principle respected everywhere
		- unified experience and tooling
		- updatable views works with all modalities
	- mutiple _-zero_ instance types
		- _-zero_ console instance
			- best for Linux/Mac/Docker
		- _-zero_ GUI instance (WPF based, requires Windows)
			- unified advanced drag and drop support among all the components
			- multiple graphical representations of same graph fragment
			- diagram viewer and editor
			- advaced text editor
	- Markdown based complex document server
